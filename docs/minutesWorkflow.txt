Drafting Minutes

Current workflow
1. Update the appropriate minutes template in src/scribe/assets/templates/ with
   meeting-specific body text such as attendance, approvals, old business, new
   business, questions, and adjournment.
   a. Templates are minutes_association.tex.j2, minutes_open.tex.j2, and
      minutes_regular.tex.j2.
2. Transfer the M4A recording of the meeting from phone to disk.
3. Generate a transcript and summary for the cycle. Review:
   src/scribe/output/cycles/YYYY-MM/transcript.txt.summary.md
4. Use the summary and meeting record to prepare minutes body text and optional
   officer narrative fragments.
   a. Store officer fragments in:
      src/scribe/output/cycles/YYYY-MM/officer_reports/
   b. Supported filenames are president.tex, vicePresident.tex, treasurer.tex,
      secretary.tex, and administrativeAssistant.tex.
   c. Fragments contain narrative paragraphs only. Officer subsection headings
      and appendix-reference sentences are supplied by the template.
   d. Review fragments for factual accuracy and LaTeX safety. Missing fragments
      are allowed.
5. Stage and format reports with module invocation:
   uv run python -m src.scribe.cli.run_cycle \
     --cycle YYYY-MM \
     --apply
6. If reports were added after an earlier staging run, rerun the applied cycle
   command above. Already-staged Gmail messages are skipped; newly arrived
   unlabeled reports are staged. Then refresh downstream artifacts:
   uv run python -m src.scribe.cli.collect_pdfs \
     --cycle YYYY-MM \
     --overwrite
   uv run python -m src.scribe.cli.format_all \
     --cycle YYYY-MM \
     --input-dir src/scribe/output/cycles/YYYY-MM/pdf
7. Build the regular minutes PDF:
   uv run python -m src.scribe.cli.build_minutes --cycle YYYY-MM --type regular
8. Before distribution, verify that expected reports, late reports, officer
   narratives, appendix references, and multi-page report appendices are
   complete and in the correct order.
9. Use the email tools to mail the draft to the appropriate addressees.

Report appendix behavior
- Do not manually edit the minutes template to specify report page counts.
- The formatter writes PNG appendix assets and records their ordered filenames
  in src/scribe/output/cycles/YYYY-MM/manifest.json.
- The minutes templates read the manifest and generate one \reportpage entry
  for each listed PNG file.
- The current appendix syntax is \reportbegin, repeated \reportpage entries,
  and \reportend. The old \report macro remains only as a compatibility
  wrapper.
- Formatter output naming is based on emitted, nonblank pages after blank-page
  suppression:
  a. one emitted page: <office>.png
  b. multiple emitted pages: <office>-1.png, <office>-2.png, etc.
- The cycle manifest should list only PNG filenames that exist on disk.

Historical note
- Older workflows required manual conversion or manual report page entries in
  the template. That guidance is obsolete for current cycle production.
